# AGENTS.md - second brain vault

Plain markdown, Obsidian-openable, no numbering scheme. People and agents both write here,
and this file is the contract that keeps it legible to both. It is the short core every job
and editor needs; each procedure lives in its own file (see "Where procedures live"). Keep it current: when
a convention changes, change it here in the same edit.

## Layout

Life-area folders hold `type: topic` notes, one folder per area of life. This vault was set up
with the set below, which is **an example, not a prescription**: rename, add or drop folders
to fit yours, and update the `pillar:` vocabulary in the same edit. A note's life area rides on
the note as a `pillar:` tag, so a note can belong to two areas at once.

{{PILLAR_BULLETS}}

Entity folders hold one fixed `type` each:

- `people/` - one note per person (`type: person`)
- `projects/` - one note per initiative (`type: project`, carries `stage: idea|active|on-hold|done`)
- `decisions/` - one note per decision made (`type: decision`)
- `meetings/` - one note per meeting, filename starts `YYYY-MM-DD ` (`type: meeting`)
- `journal/` - one note per day, filename `YYYY-MM-DD.md` (`type: daily`)
- `reviews/` - periodic review notes, filename starts `YYYY-MM-DD ` (`type: review`)
- `sources/` - one note per raw file ingested (`type: source`, plus the provenance keys below)
- `preferences/` - optional, one note per project on how to work on it (`type: preference`)

Everything else:

- `START-HERE.md` - the tour for people, and the commands for daily use and search
- `MAP.md` - generated by `bin/index.mjs`: one line per note, grouped by folder
- `templates/` - one frontmatter and body template per note `type`
- `bin/` - the vault's scripts (index, check, ingest, housekeeping, and the optional tools)
- `prompts/` - the prompts the scripts hand to your agent CLI, one per job
- `.ingest/ledger.tsv` - what has been ingested; the first `bin/ingest.mjs` run creates it
- `maps/`, `docs/`, `data/`, `systemd/`, `tests/`, `.cache/` - optional folders for generated
  maps, housekeeping docs and the vault's own jobs; they hold no notes and `bin/check.mjs` skips them

`START-HERE.md`, `MAP.md`, `AGENTS.md`, `CLAUDE.md` and a folder's own `README.md` carry no note
frontmatter, and `bin/check.mjs` skips them. Raw source files live **outside** this vault, under
`$RAW_DIR` (this setup: `{{RAW_DIR}}`). Notes in `sources/` name them by exact filename only.

## What's open

`decisions/`, `journal/` and `reviews/` are where unresolved things live, so the next reader
meets them:

- `decisions/` holds what has been settled and why, so a closed question stays closed and a
  reopened one shows what changed.
- The most recent `journal/YYYY-MM-DD.md` holds today's carried-over state. It is transient:
  sweep it into real notes and let it go.
- `reviews/` is where the sweep happens on a schedule, and where a project's `stage:` changes on
  purpose rather than by drift.

An open item is true only as of its date. Check it against the live tracker or repository
before acting on it. Before changing notes, read the latest `journal/` note and the decisions
`MAP.md` lists for the topic at hand.

## Note contract

Every note under a life-area folder or an entity folder MUST open with this frontmatter. See
`templates/` for one file per type.

```yaml
title:    <string>
type:     source|topic|person|project|decision|meeting|daily|review|preference
status:   draft|current|superseded|archived
pillar:   [{{PILLARS_INLINE}}]   # list, at least one value
lang:     {{LANGS}}
created:  YYYY-MM-DD
updated:  YYYY-MM-DD
```

- A project note also carries `stage: idea|active|on-hold|done`.
- A `sources/` note also carries `source` (the exact original filename), `ingested`
  (YYYY-MM-DD), `sha256`, and `filetype` (`eml|md|xlsx|pdf|txt|html|other`, the file kind).
- A note's `type` matches the fixed type of its entity folder. Update `updated:` on every edit.
- `bin/check.mjs` enforces all of this, and that every `[[wikilink]]` resolves to a note that
  exists. A note with broken frontmatter is invisible to every filtered read of the vault.

**Provenance.** Every fact added to a topic, person, project, decision or meeting note carries
its origin inline: `(from [[<source note>]], <date>)`, or `(captured by <who>, <date>)` when it
came from a conversation rather than a file. The newest dated line wins.

**Dated lines.** A fact that contradicts an existing line is never overwritten. Strike the old
line, stating both dates, and add the new fact as its own line below:

```markdown
~~The deadline is 14 March (stated 2026-01-08)~~ superseded 2026-02-19 by the line below.
The deadline is 4 April (from [[budget-revision.eml]], 2026-02-19).
```

A merged note becomes a one-line `status: superseded` redirect to the note that replaced it.

**Writing style.** No em dashes in new prose: use a period, a comma, a colon, or a plain
conjunction (quoted source material stays as it is). Write the fact, not the story around it,
one claim per line, each with its provenance. Prefer a link (`[[note]]`) to a retelling.

## How to find something

Find a note by folder and file name first (`ls projects/`, `rg -l "phrase" .`), then read it.
`MAP.md` lists every note, one line each. `bin/search <terms>` ranks notes by those words when
it is installed (`--json` for agents). Trust the newest dated line, follow a
`status: superseded` redirect to its note, and check an open item against the live tracker or
repository, since notes lag behind them. Details: `START-HERE.md`, "Searching".

## Hard rules

- **Raw files are never copied into the vault, and never modified.** `$RAW_DIR` is the archive,
  this vault is notes about it. The `sha256` in a `sources/` note is the only link that has to
  survive a rename.
- **No search or embedding index.** Agents read and grep the vault directly. A note that cannot
  be found by its folder and file name, `MAP.md` or `rg` is a badly written note, not a missing
  index.
- **No local models** for understanding, summarizing or writing notes. Plain extraction tools
  that recover text from a file without interpreting it are fine ahead of the agent run.
- **No credential ever enters the vault**: no secret, token, API key or password, in any folder.
- **Tasks never live in the vault.** The task tracker holds the queue. A project note names the
  next action and where it is tracked, and never mirrors the task list.
- **Nothing is silently deleted or overwritten.** A wrong fact gets struck, not removed.

## Where procedures live

Each procedure lives in one file, and every script opens with a usage comment.

- Ingest raw files: `START-HERE.md`, "Daily use", for the commands; `prompts/ingest.md` for
  what one run writes and how duplicates, revisions and timeouts are handled.
- Check and reindex: `START-HERE.md`, "Daily use" (`bin/check.mjs`, `bin/index.mjs`,
  `bin/housekeeping.mjs`).
- Search: `START-HERE.md`, "Searching" (`rg`, and `bin/search` when installed).
- Capture one fact (when installed): the usage comment in `bin/capture.mjs`.
- Garden (when installed): `prompts/garden.md`, and the usage comment in `bin/garden.mjs`.
- Bookmarks (when installed): the usage comment in `bin/bookmarks.mjs`.

## Maintaining this file

Keep this file for what almost every job and editor needs. A procedure goes in its own file,
with one pointer line here. Prefer rewriting or pruning an entry over appending a new one.
